# 🌐 Dia 01 — Fundamentos de Redes e Reconhecimento

## 🎯 Objetivo

Compreender e verificar, na prática, a configuração de rede do CyberLab, analisando interfaces, endereçamento IP, rotas, conectividade e portas abertas.

O objetivo também foi relacionar os conhecimentos de redes com os conceitos estudados anteriormente em Linux, principalmente processos e serviços.

---

## 🧠 Conceitos estudados

### Interface de rede

A interface de rede é o componente responsável pela comunicação do sistema com uma rede.

Comandos utilizados:

```bash
ip addr
ip link
```

Esses comandos permitem verificar interfaces, endereços IP, estado da interface e outras informações relacionadas à conectividade.

---

### Endereço IP

O endereço IP identifica logicamente um dispositivo dentro de uma rede.

No CyberLab, a comunicação entre as máquinas foi configurada utilizando a rede:

```text
10.10.10.0/24
```

Com as máquinas do laboratório utilizando:

```text
Debian → 10.10.10.10/24
Kali   → 10.10.10.20/24
```

---

### Tabela de rotas

A tabela de rotas informa ao sistema como os pacotes devem ser encaminhados.

Comando utilizado:

```bash
ip route
```

Também foi utilizado:

```bash
ip route get 10.10.10.20
```

e, no Kali:

```bash
ip route get 10.10.10.10
```

Esse comando permite verificar qual rota e interface serão utilizadas para alcançar determinado destino.

---

## 🔄 Teste de conectividade

Foi realizado o teste de comunicação entre Debian e Kali utilizando ICMP:

```bash
ping -c 4 10.10.10.20
```

No sentido contrário:

```bash
ping -c 4 10.10.10.10
```

O teste permitiu verificar a conectividade entre as duas máquinas do CyberLab.

### 🔎 Observação de segurança

O funcionamento do `ping` demonstra conectividade através de ICMP, mas não significa que todos os serviços TCP ou UDP estejam disponíveis.

Por isso, a análise precisa avançar para portas e serviços.

---

## 🔍 Análise de portas

No Debian foi utilizado:

```bash
ss -tuln
```

O comando permite visualizar sockets TCP e UDP em estado de escuta.

No Kali foi utilizado:

```bash
nmap -n 10.10.10.10
```

O Nmap permitiu observar as portas TCP acessíveis no Debian a partir do Kali.

## 🔗 Correlação entre rede e Linux

Um dos principais aprendizados do dia foi relacionar conceitos de redes com o conhecimento adquirido na Week 03.

A investigação pode seguir a cadeia:

```text
IP
 ↓
Porta
 ↓
Serviço
 ↓
Processo
 ↓
Evidência
```

Por exemplo, uma porta aberta não deve ser analisada isoladamente.

É necessário identificar:

* Qual porta está aberta?
* Qual protocolo está sendo utilizado?
* Qual serviço está associado?
* Qual processo está executando o serviço?
* Existem logs relacionados?
* O serviço deveria estar disponível?

---

## 🛡️ Perspectiva de Cybersecurity

A identificação de portas e serviços é uma etapa importante no reconhecimento de um ambiente.

Do ponto de vista defensivo, conhecer a superfície de exposição permite identificar:

* serviços desnecessários;
* portas inesperadamente abertas;
* serviços que precisam ser protegidos;
* possíveis pontos de investigação;
* diferenças entre o estado esperado e o estado observado.

O objetivo não é apenas descobrir uma porta aberta, mas entender **por que ela está aberta e qual componente do sistema está por trás dela**.

## 🧠 Principal aprendizado

O Day 01 mostrou que uma análise de segurança de rede não deve ser separada da análise do próprio sistema.

Uma porta aberta representa apenas o início da investigação.

O próximo passo é descobrir **qual serviço está por trás dela, qual processo o executa e quais evidências o sistema registra sobre seu funcionamento**.
