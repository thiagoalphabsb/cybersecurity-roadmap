========================================
9. CONCLUSÃO
========================================

Resumo:
A investigação correlacionou com sucesso a cadeia completa entre Soquetes TCP, PID, Processo, Serviços de Suporte, Permissões de Token de Usuário, Filtro do Firewall e Logs de Segurança do Windows. A conexão analisada é estritamente legítima e operacional.

Evidências coletadas:
- Tabela de conexões TCP via Get-NetTCPConnection
- Mapeamento de PID para Processo e Caminho do Executável via Get-Process
- Inspeção de Token e Privilégios via whoami /priv e whoami /groups
- Identificação de Serviços Vinculados via Get-CimInstance Win32_Service
- Validação de Regras do Windows Defender Firewall via Get-NetFirewallRule
- Correlação de Logs de Autenticação no Event Viewer (IDs 4624 / 4625 / 7036)

Principais aprendizados:
1. Um usuário pertencer ao grupo Administrators não significa que todos os seus processos rodam com privilégios administrativos ativos; a estrutura de Tokens e UAC filtra esses privilégios.
2. A análise isolada de um IP ou Porta é insuficiente. A investigação real exige seguir a cadeia completa: IP:Porta -> PID -> Processo -> Caminho -> Usuário -> Serviço -> Log.
3. Entender a diferença entre ferramentas administrativas do Linux (`ip`, `ss`) e do Windows (`Get-NetIPConfiguration`, `Get-NetTCPConnection`) fortalece a resposta a incidentes multiplataforma.
